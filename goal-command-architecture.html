DeepSeek Harness / Runtime anatomy 01

一条命令，两个状态世界

/goal 不直接“让模型继续”。它先提交一个可重放的目标事实，再由独立驱动器把这个事实转化为下一轮普通 Agent 输入。持久状态与运行权限始终分离。

核心公式

Command → GoalService → goal/change → goal/changed → checkpoint → Agent.followup → user/message

01 / PARSER

语法很窄，目标很宽

解析器只占有五个完整控制词。除这些精确形式外，任何非空后缀都被视为目标文本。因此 /goal pause after verification 创建的是字面目标，而不是 pause 命令。


        

        
模型不会参与命令分发。 ctx.commands 直接调用 Handler；命令输入、状态文本和错误文本都不进入模型请求。只有后续 Goal Round 才会把目标状态转成模型可见的普通 user/message。

03 / TWO TRACKS
Phase 不是 Activation

          
Goal 的“事实状态”和“能否自动继续”解决的是不同问题。恢复 Session 时，日志仍可投影出 active，但新的进程绝不会继承旧进程的自动执行权限。

05 / RACE FENCES
为什么不会无限乱跑

          
自动续行不是一个 while(true)。Driver 在每轮之前跨越持久化、身份、revision、Inbox 和 Agent 生命周期多道护栏，并在不确定时关闭权限。

        

        

          
FENCE / CAS
精确 revision
所有变更携带 { id, revision }。若当前 revision 已变化，旧命令或旧 Round reservation 被拒绝，防止覆盖新目标。

          
FENCE / DURABILITY
先 flush，再调度
goal/changed 产生持久化义务。Driver 在排队下一轮前等待 ctx.sessions.flush()，然后重新检查竞争输入和状态。

          
FENCE / ADMISSION
认领后再验一次
agent/pre-step 校验 Goal id、revision、round、phase、activation 和消息内容。任何过期 reservation 都关闭该 Step。

          
FENCE / FAIRNESS
人类输入优先
普通 next-turn 消息出现时，Driver 标记 competingQueued，不抢在用户输入前自动开始新的 Goal Round。

          
FENCE / BUDGET
Round 上限
只有已经进入 Session 的 Goal 来源 user/message 才推进计数。达到上限后持久化为 blocked: round-limit。

          
FENCE / FAIL CLOSED
错误即 disarm
Agent 错误、flush 失败、Driver 卸载或请求达到 max-tokens 时，自动续行权限被移除，避免在不确定状态继续执行。

        

      


      

        

          
06 / SOURCE MAP
四个包，各守一责

          
源码边界刻意阻止命令、领域状态和调度策略混在一起。下面链接以本 HTML 所在的仓库根目录为基准。

        

        

          ADAPTER
command-goal
解析斜杠输入、调用领域动词、渲染直接 UI 文本；不拥有 Goal 状态。

          DOMAIN
goal
验证状态转换、CAS revision、追加 goal/change、投影当前 GoalView。

          POLICY CONSUMER
goal-round-driver
监听提交后的变更，执行 checkpoint，构造下一轮消息并处理竞态。

          MODEL SURFACE

          MODEL CONTROL
tool-goal

          REFERENCE
