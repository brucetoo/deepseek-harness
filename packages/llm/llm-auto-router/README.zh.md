# @deepseek-ai/dsh-llm-auto-router

[English](README.md) | 中文

面向 Agent 请求、可用性优先的自动模型路由。显式模型选择保持固定；Auto 选择会在每次物理尝试时，依据兼容性、进程内健康状态、首 token 延迟和进行中负载，从配置的池中解析路由。

## 配置

除非配置替换，`default` 池包含所有已发布的 `provider/model` 路由。命名池接受 include 和 exclude 模式。`models` 以规范 `provider/model` 为键；每个显式路由需指定池和并发限制，也可设置 `enabled` 或 `preferenceMultiplier`。显式条目可以添加提供方目录未发布的路由。

路由器会排除声明的模态、上下文容量、输出余量或推理档位无法满足请求的路由。缺少必要元数据时，路由不具备资格。生成的[配置目录](../../../docs/config-catalog.zh.md)列出评分、token 安全余量、探索、失败阈值、冷却、半开探测和单步故障转移上限的默认值。

只有解析后策略以及所属 Context 和服务身份完全相同的插件实例才共享健康状态。不兼容的进程全局复用会在插件应用时失败。成功的终止 finish 会更新延迟并清除失败；提供方错误 finish 会更新失败和熔断状态。取消、请求准备失败、未完整结束的流和包装器错误只释放容量，不惩罚提供方。

## 选择与故障转移

`model/selection` 独立于物理请求头保存逻辑 Auto 或具体模型意图。Auto 提示变量保持 `provider=auto` 和 `model=auto`；物理 provider/model 由 `request/header`、路由事件和助手来源记录。

路由器只能在输出提交前切换路由。非空文本或推理增量、任意工具调用增量和 `block-end` 都会提交一次尝试。委托迭代器成功进入后、产出首个 chunk 前才会追加路由事件；构造或首次读取失败不会留下路由事件。上下文溢出仍由压缩功能处理。其他 request-error 监听器决定重试时，路由器会把该次重试固定到同一物理路由，并仅在替换预留成功后消费该固定项。

## 模型体验

### 自动请求路由

#### 模型看到的内容

插件不会添加提示文本、消息、模式或工具结果。所有物理尝试接收相同的已组装消息。Auto 变量保持为逻辑元数据（`provider=auto`、`model=auto`），不会在提示中暴露选中的物理路由。

#### Token 影响

插件不添加 token。它使用完整请求头分别测量每个候选，并排除无法容纳实测输入、请求或默认输出以及配置安全余量的路由。

#### KV 缓存影响

同一物理路由上的重试保留常规提供方缓存机会。跨路由故障转移使用其他 provider/model，可能无法命中提供方本地缓存。

## 已知限制和延期工作

- **健康状态仅存在于进程内** — 进程重启时，延迟、失败、熔断和并发状态会重置。
- **兼容性依赖元数据** — 缺少所需模态、上下文、输出或推理声明的路由不具备资格。
- **Auto 不支持选择推理档位** — 自动意图不携带推理档位偏好；需要指定档位时请选择具体模型。
- **request-error 缺少模型字段** — 核心事件只标识提供方，因此路由器还会把最新已派发尝试与当前物理请求头核对。在核心事件携带模型或尝试身份前，精确归因依赖这份插件自有状态。
