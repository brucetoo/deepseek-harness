# Agent Note: 桌面端内置文档与调研工作流

Status: implemented

[English](2026-09-15-desktop-bundled-workflows.md) | 中文

## 问题

Electron 应用携带自包含 Host，但全新安装无法可靠生成可编辑 Office 文件。用户级技能与系统 Python 或 Node 包会随机器变化。现有 web 工具能够获取公开网页，但底层搜索与抓取操作没有定义可重复的「调研到成果」工作流。

二进制文件也不会经过文本修改工具，而成果文件 UI 正是从这些工具的展示 `locations` 获取数据。从终端文本或目录扫描推断输出，无法区分预期成果、临时文件和无关文件。

## 决策

桌面运行时在 deploy 根目录下提供三个只读内置技能：`office-docx`、`office-xlsx` 与 `browser-research`。Electron 通过 `DSH_BUNDLED_SKILL_DIR` 传入该目录；既有文件系统 skill provider 会以 bundled rank 加载它。sidecar 还会向 shell 命令提供 `DEEPSEEK_HARNESS_DESKTOP_NODE` 与 `DEEPSEEK_HARNESS_BUNDLED_SKILL_DIR`。这些名称位于 shell 每次调用都会重建的托管 `DSH_*` 命名空间之外，因此 subprocess scrub 会保留确切的暂存可执行文件和技能路径，而不会把环境中的值当成可信 Session 事实。

DOCX 生成器使用维护中的 `docx` 包，接受由标题、副标题、章节、段落、真实 Word 列表和表格组成的有界文档词表。XLSX 生成器使用 `exceljs`，接受工作表、列、行、可选冻结表头与筛选器，以及携带非错误缓存结果的公式。两者从文件或 stdin 解析 JSON，验证必填字段，经临时文件写入请求的输出路径旁，并且只发布 `.docx` 或 `.xlsx` 目标。

浏览器调研技能组合既有 `web_search`、`web_fetch` 与 `write` 工具。它要求优先使用一手来源、尽可能交叉验证重要声明、提供行内引用，并生成本地 Markdown 报告。它明确不声称具备交互式浏览器控制能力。

`register_artifact` 是二进制生产方的持久交接。agent 作用域内的文件系统工具套件拥有它，因此进程级全局工具层保持为空，省略 `dsh-tool-fs` 的 preset 也不会继承此工具及其提示词。它通过 `ctx.fs` 解析 workspace 相对路径，要求目标为现有普通文件，记录文件系统观察结果，并发布一个 edit kind 的展示位置。因此，普通工具日志即可重建已完成的登记与成果 UI，无需另一种持久化格式。

暂存流程会拒绝缺少任一内置技能入口、生成脚本或 `docx`、`exceljs` 依赖的运行时。脚本从已部署的 `app/node_modules` 树解析这些包。

## 考虑过的替代方案

**依赖 Python、LibreOffice 或全局安装的 npm 包。** 这能够提供更丰富的编辑与重算能力，但会让干净的桌面安装依赖宿主环境，破坏自包含打包要求。

**直接构建 OOXML 压缩包。** DOCX 与 XLSX 都是基于 ZIP 的格式，但手写 XML 会重复维护成熟库已经完成的工作，并增加文件损坏与兼容风险。

**从 Bash 输出或 workspace 扫描推断成果。** 终端文本没有权威路径格式，workspace 差异还会与无关写入竞争。显式登记能够标识预期的现有文件。

**把网页搜索称为浏览器自动化。** 搜索与 HTTP 获取覆盖调研，不具备登录、点击、填写表单、上传或视觉交互语义。区分命名能够避免产品承诺尚不存在的控制路径。

## 验证

单元测试通过 Node 执行两个生成器。DOCX 验证会解包归档并检查文档文本、编号和表格；XLSX 验证会重新载入工作簿，并检查冻结表头、筛选器、公式、缓存结果与公式错误拒绝。桌面生命周期测试固定注入路径，暂存测试要求每个技能、脚本与运行时依赖存在。客户端测试覆盖跨 Turn 汇总、排序、历史分页、文件打开、登记与插件卸载；组装层组合测试固定模型可见工具与提示词。

## 后果

打包后的桌面安装无需外部语言运行时，即可创建新的 DOCX 与 XLSX 成果，并把网页调研转成带引用的 Markdown 文件。二进制生成后经过显式登记，会与文本文件一起出现在同一持久成果视图中。

首版 Office 词表有意不编辑现有文档、不渲染预览、不通过 Office 引擎重算公式，也不生成 PPTX。浏览器调研不控制交互式浏览器。这些能力需要单独的 provider，而不能成为技能中的隐含假设。
